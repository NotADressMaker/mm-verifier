# Program governance

Every program version declares its author or organization, creation date, changelog, and evidence-admissibility rules in `program_provenance`. Those declarations are committed with the program and copied into receipts; they identify the policy author, not an evidentiary authority.

## Disputing a program

A program dispute concerns whether its admissibility rules, claim domain, scenario construction, or versioned policy are appropriate. It is distinct from a verdict dispute, which challenges claim-to-evidence relations in one receipt. Reviewers should preserve the challenged manifest and receipt, identify the disputed rule and proposed replacement, and request a new program version rather than edit history. The existing `DisputeLadder` process and auditor duties govern escalation and review; this document adds program-policy review to that machinery rather than creating a parallel forum.

A program review may find rules incomplete, overbroad, or unsuitable. It does not retrospectively establish or negate the factual correctness of a receipt's sources.
